> A4 miss率百分之百这一块 😭

!!!info "课程信息"
    - 学期：2025-2026 春夏
    - 学分：4.0
    - 教师：**李环**老师 、**陈刚**老师
    - 分数构成：
        - 作业 10%：每次课后都会布置几道教材习题作为课后作业
        - quiz 10%：一共四次（也好像是三次，记不清了），应该是参加了就给分
        - lab 30%
            - lab1-4都是基础的小实验，主要是用来熟悉sql语法
            - lab5 图书管理系统
            - lab6 MiniSQL
        - 期末 50%（一纸开卷）

### 理论课

- 这门课虽然写着是**李环**老师和**陈刚**老师授课，但院长本学期只来上过一次课（讲SQL语法），其余时间均由lh老师授课。作为年轻老师，lh老师上课水平还是很不错的，思路清晰而且幽默风趣，有一次还用Ahaslides来帮助大家复习半个学期的内容。至于quiz，lh老师每次都会提早在群里说“请大家准备好纸笔”。~~（其实就是小测的意思）~~
- 但是DB的内容实在是太多太多了，三节课的DB能坚持到第二节课下课就已经是胜利了，期末复习的时候面对加起来1000多页的ppt实在是令人头大。建议大家平时还是好好学，不然期末补天过于痛苦。

### 实验课

最复杂的两个实验就是图书管理系统和 MiniSQL。

- 图书管理系统需要独立完成，实验已经给出了MySQL + JDBC的代码框架，我们只需要完成部分模块（实现几个函数）即可，bonus 是实现图形化界面（Web页面），在Claude Code和Codex流行的当下，其实完成这些任务以及该不复杂了，助教验收的时候也没有过多提问，只需要实现功能即可。

- MiniSQL是 3 人组队完成，主要使用C++实现，开发环境最好是linux或者mac，在用windows的同学最好装个双系统或者wsl。MiniSQL的工程量非常之大，建议大家一定要早点完成，否则会影响期末复习。但正如上面所说，在LLM如此发达的现在，完成一个miniSQL已经不是非常复杂的任务了（在这里向前AI时代的老一辈程序员致敬），不过在完成实验的过程中一定要自己查看代码逻辑，了解具体功能。MiniSQL的验收还是比较严格的，助教会针对代码和逻辑向每个人提问，因此千万不要纯vibe完就直接去验收，还是要人工review并理解代码。

### 期末

正如上文所说，DB的内容实在是太多太多了，复习起来也是极度折磨。个人复习顺序也和CA一样，选择**课程笔记->朋辅->抄A4->历年卷**，但是今年DB和CA考试时间就隔了不到24个小时，我中间还塞了个毛概，导致复习时间非常紧张，那三天就基本没睡过好觉。今年的题型和24-25类似，但和24以前有较大差别，而且今年考了很多细节性的东西（很多都在PPT犄角旮旯的地方），比如第一题的BLOB我就完全不知道，query processing的四个流程我也完全没印象，虽然一个半小时就写完试卷了，但有很多题是完全不确定的，整体做下来很奇怪，总之感觉要药丸，只能寄希望于老师和助教捞捞了
